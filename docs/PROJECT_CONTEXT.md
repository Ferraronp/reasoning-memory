# Контекст проекта

Основная гипотеза Артура: представление собственного прошлого модели как компактных,
повторно используемых результатов может улучшить решение задач, требующих объединения
ранее полученных результатов. Мотивация — уменьшение расстояний и количества подробного
текста между ними. Механизм attention отдельно доказывать на первом этапе не требуется.

Всё происходит внутри одного think. Модель открывает эксперимент, завершает его и
пишет вывод. После каждого вывода система ОБЯЗАТЕЛЬНО удаляет эксперимент из активного
контекста и перестраивает затронутый cache. Отдельного решения «что удалять» нет.
Полный эксперимент хранится под ID и может быть выборочно восстановлен.
Summary переносит информацию текстом; скрытого переноса через старый KV быть не должно.

Цель — качество, не преимущественно память/ускорение. ARC-AGI не выбран; речь о сложном
рассуждении в целом. Вложенность отложена. Новизна не подтверждена, ближайшую литературу
нужно отдельно перепроверить перед научными утверждениями.

Ресурсы: у пользователя есть GTX 1660 Super, предполагаемая площадка — Google Colab T4.
Маленькая модель нужна для первоначальной отладки. Предпочтение для основных тестов —
около 9B, вероятно INT8. Начальные технические прогоны — 16-битные веса без квантизации.
Загрузка 9B FP16 на T4 не планируется. Длина контекста и память определяются измерением.

Код хранится в .py, ноутбук служит точкой запуска. GitHub-репозиторий:
https://github.com/Ferraronp/reasoning-memory (private). Первая ячейка Colab
клонирует/обновляет main без перезаписи локальных правок. Других агентов
пользователь, возможно, подключит позднее; данная версия сделана без делегирования.

Статус v0.2: пользователь запустил Qwen3-0.6B FP16 в Colab. Модель дала число 5,
но не выдала experiment/summary-теги; свёртка не выполнялась. Исправлена отчётность:
такой исход — один сбой общего префикса, а не два провала сравниваемых политик.
Добавлен guided_single с границами, задаваемыми контроллером, как отдельный
технический тест. Самостоятельный выбор границ остаётся целью автономного режима.
Результата о пользе забывания пока нет.

В следующем пользовательском guided-прогоне модель сразу закрыла пустой XML-эксперимент. В v0.2.1 guided использует обычный текст рассуждения и вывода; ID/границы находятся в контроллере. GPU-проверка нового prompt ожидается.

## 0.3.1 — 1.7B и сравнение подачи второго этапа
Пользователь выбрал следующий размер: Qwen/Qwen3-1.7B, FP16.
В ноутбуке два запуска на одинаковых задачах, seed и бюджетах:
`configs/qwen3_17b_fp16_two_stage.json` — прежняя подача внутри think;
`configs/qwen3_17b_fp16_chat_two_stage.json` — новое пользовательское сообщение.
Второй режим называется `guided_chat_two_stage`: первый вывод размещается как
ответ ассистента вне think, затем добавляется user turn и новый think. Full
сохраняет первый reasoning без изменений, compact удаляет его. История не
пропускается повторно через chat template, чтобы шаблон не удалил reasoning full.
Адаптер перехода рассчитан на Qwen3. Это отдельная диагностика, два thinking-блока,
не реализация целевого автономного протокола внутри одного think.

Откройте свежий ноутбук, выполните обновление и установку (doctor: 0.3.1),
затем две ячейки двухэтапного теста, сначала LIMIT=1. Старые smoke можно пропустить.
Ожидаемый ответ 17; на всех трёх задачах — 17, 25, 53. Exact match остаётся строгим.
Код проверен на искусственных ответах, реальная модель проверяется пользователем
в Colab. Нельзя считать исправление подтверждённым до этого запуска.

Предыдущий реальный прогон 0.6B (20260923T131518_215660Z): первые этапы и выводы
арифметически верны; compact во всех трёх задачах сразу генерирует </think> на

## 0.3.2 — результаты 1.7B и исправление продолжения в диалоге
В реальном прогоне Qwen3-1.7B FP16/T4 с seed42 `guided_two_stage` завершил
первый этап, но сразу сгенерировал `</think>` во втором и в full, и в compact.
Увеличение модели с 0.6B до 1.7B само по себе не решило проблему подачи второго
этапа внутри одного thinking-блока.

В `guided_chat_two_stage` обе ветки вычислили 17 во втором рассуждении;
full затем сгенерировал `17` с EOS во время навязанного запроса summary, и
контроллер ошибочно счёл это незавершённым. Compact завершился текстом
`Conclusion: 17`, который не совпал с ожидаемым `17` при строгой проверке.
В новом режиме второго чата 0.3.2 после второго рассуждения контроллер закрывает
thinking и запрашивает обычный финальный ответ. Именно ответ модели сохраняется
как второй вывод. Он не редактируется и не приводится к числу контроллером.
Компактация e2 выполняется лишь после полного ответа; при обрыве его тело
остаётся в активном контексте, архив e2 не создаётся. Это диагностический
вариант с двумя сообщениями, а не проверка автономного протокола в одном think.

Для повторного прогона достаточно переоткрыть ноутбук или выполнить его первую
ячейку обновления и ячейку установки, убедиться в версии 0.3.2, затем запустить
только ячейку `guided_chat_two_stage` после задания `LIMIT = 1`. Предыдущий
внутренний двухэтапный режим уже диагностирован, его повторять не требуется.

## 0.3.3 — раздельная оценка завершения и точности
Ошибки протокола и незавершённые генерации больше не попадают в знаменатель
accuracy. Поле `correct` у нового незавершённого результата равно null; `failed`
считает незавершённые задачи каждой ветки. `scored` считает только завершённые
задачи с ожидаемым ответом. Исторические логи с `correct=false` у ошибок
`summarize` также исключает из accuracy. Дополнительно всегда смотрите
количество completed и failed: успешная точность при малом completed не
характеризует модель на полном наборе.

## 0.3.4: подтверждённый диалоговый тест и ноутбук
Реальный запуск пользователя 20260923T172719_194693Z, Qwen3-1.7B FP16,
Tesla T4, seed42, guided_chat_two_stage: full completed answer=17
correct=true, active_tokens=699; compact completed answer=«Conclusion: 17»
correct=false (строгий формат), active_tokens=150. В каждой ветке 2 эксперимента,
без ошибок протокола. Финальные входы показали, что в compact второй reasoning
перед ответом ещё присутствует; его удаление выполняется после полного ответа.
Пара подтверждает техническую работу ветвления и архива, но не необходимость
использования вывода: исходная задача доступна и может быть пересчитана.
В этом же архиве guided_two_stage на 1.7B вновь завершился ошибкой на старте
второго эксперимента, по одному токену `</think>` в обеих ветках.
Ноутбук сокращён до актуальной диагностики без автоматического mock и старых
режимов. Doctor печатает только версию, коммит (если доступен) и сведения о GPU;
полный environment.json при эксперименте сохраняется для воспроизводимости.

## 0.3.5 — усложнённый диагностический набор
Три задачи на два этапа: композиция двух функций (a=4,b=3,c=3,d=6,
ответ87), зависимые значения (A25,B19,C13,D57, ответ222), кратчайший путь
A-B-C-D-E вес11, внутренние вершины B,C,D дают5+7+11=23, итог45.
Вторая часть каждой задачи раскрывается только после общего первого summary.
Colab показывает само summary и входные токены второго этапа у каждой ветки.
Это всё ещё диагностика механики, а не доказательство выигрыша памяти:
исходное условие доступно в обеих ветках, автозамены неправильных ответов нет.
Если подготовительный вывод неверен, фиксировать отдельно от ошибки второго этапа.
